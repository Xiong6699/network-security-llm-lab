# 典型样本与实际切片演示

v2 在 11 个基础样本之外，新增 3 个流程样本。典型性由业务关系和漏洞判定难度决定，不以单纯行数衡量。当前共 14 个父样本、26 个代码片段，四类审计范围；切片不能被当作新增独立样本或漏洞数量。

## SQLI-005

```text
注册参数 → 转义 → users表写入
                    ↓
登录参数 → 查询 → 数据库username → SESSION.username
                                      ↓
改密参数 → 当前密码和新密码处理 → UPDATE使用SESSION.username
```

P1 提供注册入口和共享连接；P2 提供完整登录、改密入口及同一连接。数据库与会话是跨请求连接，不能只给模型最后的 UPDATE 一行。反之，看到注册转义也不能提前推断后续使用安全。模型需综合所有阶段，再由验证组实测。

这是固定提交的原始 Less-24。其大小写冲突文件不从 Windows 工作树提取，而从 Git 对象读取；完整部署优先在 Linux。保留混合 HTML/PHP，是因为 PHP 标签之间的实际输出、header 与会话启动顺序可能影响运行，不套用短样本的简单提取方法。

## XSS-005

```text
留言POST → 写入处理器A → guestbook表
                            ↓
再次请求 → 页面处理器B → 读取函数C → HTML字符串 → 页面输出
                            ↑
                      配置读取函数D
```

提供完整写入与读取代码，区分 SQL 转义与 HTML 输出编码。保留表单参数、maxlength、清理按钮与条件编码分支。当前 A 对应上游选定写入版本；其他写入版本未提供，不能将 A 自动套用到所有配置。验证人员需确认页面实际包含的写入文件。

这一流程只有 150 行，完整放在一个输入包更合适，不为演示切片而拆碎。

## AUTH-001

```text
管理页面A → 页面角色检查C → 浏览器脚本B
                                 ├→ 列表接口D
                                 └→ 更新接口E
身份与配置函数F → 页面、接口与渲染函数G
渲染函数G → 菜单可见性和页面输出
```

P1 为页面、客户端、角色检查和身份配置；P2 为两个独立接口及身份配置；P3 为完整渲染函数及身份配置。F 在三个包中重复提供，让各包保有相同的身份与配置判定上下文。

业务权限约定“仅admin可读取或修改全部用户资料”是判断越权所必需的规格，不是预先提供漏洞结论。原代码中 high/impossible 等字符串属于实际控制条件，不能为隐藏靶场等级而删除。角色检查片段前的教学提示评论已排除，执行语句保留并逐行映射。

## 切片依据

本批输入包采用 220 代码行的工作上限，按完整处理器、完整函数和业务阶段组织，未截断字符串、条件、查询或参数列表。它是课程实验的可检查预算，不等于某个模型的 token 上限；组2选定模型与完整 Prompt 后应再次检查实际输入预算。

优先重复完整依赖函数，而不是机械复制前后10行。AUTH-001 的 F 为45行，SQLI-005 的共享连接 D 为37行，这种结构重叠比从处理器中途切20行更能保留语义。本批文件本身可独立成边界，没有对单个长字符串或长函数再按行数截断。

每个包先输出局部证据与缺失依赖，再综合父样本全部包形成结论。可在同一对话分包追加；若总上下文仍不足，先保存带片段ID和局部行号的结构化摘要，再进入综合阶段，不声称分包自动解决所有上下文限制。

## 实验安排建议

所有样本用于章程规定的LLM分析与人工POC验证。记录模型结论、代码证据和实测结果，并用于Prompt迭代；不额外安排代码版本配对或局部/完整输入的对比实验。

所有最终标签仍需验证。当前只有源码追溯、映射、关键操作和分包依赖的静态检查；没有运行 LLM、PHP 或 POC，也没有准确率提升结论。
