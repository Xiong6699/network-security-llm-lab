# 模块2 Prompt提示词工程

本模块接收工作包1的v2标准输入，采用四段式Prompt约束LLM给出代码位置、原理、条件和本地POC草案。沿用14个父样本、26个片段和17份输入包，覆盖SQL注入、XSS、命令注入和权限越权；不改写上游输入。当前成果为提示词设计、两轮设计修订和同一Codex会话的初步试用，尚无独立模型评测及POC实测指标。

## 通用结构与设计依据

角色定义限制在授权代码及实验范围；核心任务要求识别入口、处理、危险操作、权限与观察点；判定标准区分必要条件、排除条件和证据缺口；输出约束统一位置、原理、影响、POC、运行说明与局限。三个版本全文保存于prompts/versions，填充后的完整输入保存于prepared。

输入采用工作包1既有ID、依赖和局部行号。数据边界、代码注释及页面教学文案只能作为数据，不允许覆盖审计指令。人工标签、难度路径、原始答案及本会话试用结果不进入正式评测输入。该设计不能证明Prompt注入风险已完全消除，也不能消除模型对熟悉公开代码的记忆偏差。

## 四类漏洞专属规则

SQL注入检查可控值进入SQL的实际位置、参数化与转义适用性，并继续追踪数据库及会话中的二次使用。XSS区分反射、存储和DOM路径，结合HTML、属性、脚本及URL上下文判断编码；数据库转义不能直接替代输出编码。命令注入保留shell参数边界、空格、过滤顺序和系统分支。权限越权分别检查菜单、页面与独立API，结合角色、对象和配置说明成立条件。

规则在prompts/rules中，不为样本预填真实答案。按类型只加入相关规则；通用v1保留基本条件，v2与final加入专属规则，便于后续在相同输入上比较。

## 输出协议与防幻觉

采用wp2-output-v1 JSON协议，样本、输入与Prompt版本分开记录。静态prediction用于后续对照真实标签，verdict区分确认、待验证和排除。high、medium、low是代码证据等级，不是漏洞概率。确认必须有相同条件的真实运行证据；本次草案不能由生成POC直接升级确认。

每条候选包含片段ID、局部行号、逐字引文、数据流摘要、原理、影响、前置条件及反例。一般风险与质量问题单列。多文件流程收到全部关联包后按父样本归并；缺包标partial，不把缺失校验当不存在，也不将重叠代码计成重复漏洞。

## POC生成与交接

要求完整脚本、依赖、参数、运行步骤、预期现象与成功条件，标明可直接运行、需人工适配或不提供，同时独立记录执行状态。默认本地授权靶场，凭据由本地文件提供，不写入版本库。SQL只做最小对照，XSS用无害浏览器标记，命令只做额外回显，越权优先只读；修改测试必须有专用对象和恢复步骤。

HTTP 200、输入回显、API的ok或Python编译通过不能单独证明漏洞触发。工作包4保存适配及实际观测，工作包3提供逐条核验条件，工作包2据反馈修订提示词。详细协议、约束与接口见prompts/output_schema.md、poc_constraints.md及handoff.md。

## 两轮修订与初步试用

第一轮从v1到v2增加证据门槛、四类专属判定和POC前置条件；第二轮从v2到final强化跨包关联、共享片段去重、配置区分和输出自检。修改依据是工作包1已提供的数据流与接口结构，全文差异和未完成项保存在prompt_iteration.md。

用户选择当前Codex对话初步试用。本会话选取四类代表及一个XSS编码对照，按三个版本整理15份分析草案，保存四份POC草案；这些不是15次独立模型调用。工具只核验JSON字段、代码引文、行号、文件对应和Python语法，不执行POC，不把静态通过当作真实定位准确率或模型提升。

## 评测与当前局限

prepare_inputs工具准备三个版本的51份逐包输入和42条评测记录。清单记录模板、规则、输入和完整Prompt哈希，不调用模型。42条记录已由独立上下文的 DeepSeek Harness 子代理运行并填入 `evaluation_records.csv`（`completed`），原始输出在 `results/batches/wp2-eval-42/`；模型快照、采样参数与用量不可取得，不能当作正式商业 API 成绩。

定位准确率需要人工核验，POC可运行率需要实际执行，误报漏报需要最终真实标签。分母为0写不适用，未测指标写待测；同样本不同角色或配置分别统计，partial不进入父样本指标。本次标签全部待验证，同源样本和同会话历史限制结论。三版分类均为14/14，但严格静态协议分别为 v1 5/14、v2 8/14、final 4/14；不能把分类结果外推为真实业务能力。
