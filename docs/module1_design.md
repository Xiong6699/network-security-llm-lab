# 模块 1 代码预处理与数据标准化

本模块将公开教学靶场中的代码整理为可追溯的 LLM 审计输入，减少装饰页面与无关说明的干扰，同时保留输入、校验、危险操作和输出路径。第二版包含11个基础样本及3个流程样本，合计14个父样本、26个片段，覆盖SQL注入、XSS、命令注入和权限越权四类。当前成果为代码整理与静态质量抽查，尚无 POC 实测结论。

## 数据源选型

SQLi-Labs 提供 SQL 拼接、登录查询及黑名单过滤场景；DVWA 提供同一 PHP 技术栈下的 XSS 与命令注入不同防护版本，便于减少语言差异的影响。两者均保留提交号和原始文件。DVWA 授权说明随包保存；SQLi-Labs 按课程指定教学来源登记，独立传播许可未核实。

固定版本：SQLi-Labs e96f21776372c8613a7e565106e62bc01a59355e；DVWA 068d974487a297c155c48722f9fcf7180a83adc4。完整目录与字段见 workpackage1/samples.csv。


## 清洗与切片

使用固定 Git 对象保存原始字节；对本批人工查看过的文件按 PHP 块提取，去除空行及非安全相关的单行注释，保留代码字符、行内注释、过滤、日志、错误处理与输出。SQLI-003 的黑名单函数和后续 Hint 输出全部保留。详见 workpackage1/preprocess_rules.md。

短片段不强制补足行数。基础样本保留完整相关PHP逻辑；流程样本按完整处理器与函数分包，未在字符串或关键调用中按行数截断。对未来长代码按函数或调用链拆分，建议不超过 220 行，必要时前后各保留 10—20 行重叠，同时添加完整跨片依赖。不能截断字符串、条件或危险调用。

## 输入与来源追溯

每个标准输入含样本 ID、审计范围、语言、入口、参数、调用关系、外部依赖、限制、代码和行号约定。模型使用标准化行号，人工通过逐行 CSV 回溯原文件。生成包装行明确标为无原始行号；唯一派生改动单独标识。原始和标准化文件同时登记 SHA256。

以 SQLI-001 为例，原始文件外围的标题与装饰图片不进入模型输入；GET 参数接收、连接 include、查询拼接与执行、结果和错误输出均保留。具体删行及映射可在原始文件、标准化文件和 line_maps/SQLI-001.csv 中复核，而非仅凭总体范围推测。

## 静态抽查

本次静态抽查覆盖14个父样本及其关联片段，具体入口、危险操作、过滤与依赖检查结果保存于 workpackage1/review_log.csv。构建与核验工具检查固定源码对象、哈希、逐行保留关系、派生修改数量、关键符号、唯一 ID、三类覆盖和台账一致性；机器结果保存于 checks/verification.json。

静态检查不能证明运行行为完全一致或漏洞真实存在。当前未检测到 PHP 命令，未执行 php -l、环境部署或 POC；人工最终标签仍为待验证。运行证据需由后续验证模块补充。

## 接口与待优化

向提示词组提供 llm_inputs 和字段模板，向推理组提供映射和依赖。验证组反馈环境适配、缺失上下文和误判后，更新输入版本并保留与旧输出的对应关系。避免将 POC 不能运行直接判为误报，或把未确认样本纳入误漏报统计。

局限包括靶场样本规模小、同源版本相关性高、运行环境未知以及模型可能识别熟悉的公开代码。后续可增加跨函数或不同项目样本，并控制来源提示对模型结论的影响。不能将本批结果直接推广为真实业务代码的检测准确率。

## 典型流程与实际切片

SQLI-005提供250行注册、登录、改密及数据库连接代码，分2包；XSS-005提供150行留言写入、读取和输出流程，完整提供1包；AUTH-001提供450行页面、客户端、独立API、身份与渲染逻辑，分3包。单包合计最大219行。共享数据库或身份函数重复提供，父样本与片段分别编号，不重复统计漏洞数量。

这一设计让实验包含直接输入、参数过滤、数据库持久化、会话传递和权限一致性等不同难点，典型性不由长短单独决定。具体选型、分包内容、依赖和限制见workpackage1/representative_cases.md。保持原缩进的做法尚未完全满足统一排版目标，应在最终报告中如实说明并按需完善。
