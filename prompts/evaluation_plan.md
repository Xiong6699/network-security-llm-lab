# 固定样本与评测办法

输入固定为工作包1的v2，共14个父样本、17份输入包。v1、v2、final各使用同一清单，准备51份逐包Prompt，对应42条父样本与版本的正式待评测记录。数量是本仓库的实施安排，不是新增课程最低要求。

## 控制条件

固定模型供应方、实际模型标识或快照、调用界面、可见参数、上下文处理、输入哈希和部署条件。不能取得的版本或参数填未知，并说明比较限制。不同模型、配置或追加上下文的输出另开批次。

每个父样本独立新建实验会话，多包按manifest顺序在该会话追加；不同Prompt版本使用新会话，不能继承上一版答案。不提供原始难度路径、标签、POC答案或trial分析。模型输出原文与人工结构化整理稿分别保存；不能修正错误后再算原始格式合规率。

输入包219行的上限是代码组织规则，不是模型token上限。正式使用前检查完整Prompt、历史包、预计输出是否能放入实际模型上下文；需要摘要或追加依赖时记录策略和哈希，三版保持一致。不能声称分包自动解决上下文限制。

## 本会话初步试用

用户选择先使用当前Codex对话进行初步试用。本对话已经读取仓库及任务要求，没有独立重置上下文，也没有独立API请求ID、可核验模型快照或温度。试用记录是助手在本会话依据版本规则整理的分析草案，不把文件数量解释为独立模型调用次数。

初步样本为SQLI-001、XSS-001、CMD-001、AUTH-001，另加XSS-004检查输出编码的排除边界。每个样本整理三版对照，实际检查协议字段、引用行号、逐字引文和Python草案语法。这里只评价可机械检查的内容，不计算真实漏洞准确率或Prompt因果提升。

## 正式记录

evaluation_records.csv保存父样本、输入与Prompt版本、condition_key、模型配置、日期、完整Prompt包哈希、原始输出和结构化输出路径、预测、定位复核、POC状态、真实标签、验证证据、状态和备注。

当前正式表已填为 `completed`：42 条记录由 DeepSeek Harness 独立上下文子代理运行，原始输出和结构化副本保存在 `results/batches/wp2-eval-42/`。该批次不是正式商业 API 快照，模型快照、采样参数与用量均不可取得；不能把它当作正式 API 成绩，也不能把 trial 草案回填为正式成绩。人工确认后才更新 ground_truth；未部署、缺上下文、未确认角色或脚本错误单独记录。AUTH-001及XSS-005的不同角色和配置分别设condition_key，不能把有条件成立的候选折成所有配置共同的标签。增加条件时新增记录，而不是把片段数作为样本数。

## 指标定义

| 指标 | 计算范围与分母 | 不计入的情况 |
| --- | --- | --- |
| 输出格式合规率 | 未经人工修正的原始结构化响应中，满足协议的个数/实际返回个数 | not_run或无原文；人工整理稿另记 |
| 引用一致率 | 行号范围与逐字引文一致的位置数/实际位置数 | 不把一致性解释为漏洞定位正确 |
| 定位准确率 | 人工确认候选定位与目标数据流正确的报告数/已完成定位复核的候选报告数 | 未复核和无法判定；无候选另记 |
| POC可运行率 | 在声明环境中完成预定验证步骤的POC数/已经实测的POC数 | 未运行；需适配前后分别统计 |
| 精确率 | TP/(TP+FP) | 无最终标签或无法判定 |
| 召回率 | TP/(TP+FN) | 无最终标签或无法判定 |
| 误报率 | FP/(FP+TN)，真实阴性样本中被预测为阳性的比例 | 无真实阴性或分母为0 |
| 误报占比 | FP/(TP+FP)，模型阳性报告中错误的比例 | 与误报率区分；分母为0 |

真实标签与预测按相同父样本和condition_key配对。存在候选视作模型阳性，未检出候选视作模型阴性；无法判定单列，不自动当阴性。只有parent综合响应进入指标，partial和共享片段不重复计数。

指标同时列分子、分母、无法判定数量和按类型计数。分母为0写不适用，不写0%；尚无实测写待测，不填虚构数值。本次小样本、同源防护版本和熟悉公开代码的记忆偏差限制结论，不能外推真实业务代码效果。

## 两轮比较

第一轮比较v1与v2的证据、场景判定和POC条件；第二轮比较v2与final的多包归并、条件区分和自检。使用相同模型、输入及条件，保存改进、退步和不变案例。没有提升时如实记录，不挑选单个好例代替全量统计。

工作包4提供实测失败原因和标签后，先区分脚本、环境、上下文与判断错误，再决定Prompt修改。修改final后使用新的明确版本名和新批次，保留旧数据。
