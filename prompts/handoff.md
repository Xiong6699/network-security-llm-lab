# 工作包2交接

本部分接收工作包1的v2标准输入，不修改其代码、样本ID、行号、标签或切片。通用Prompt、四类规则及输出协议在prompts中，完整逐包输入由prepare_inputs生成。final是设计冻结版，实测结果仍需后续模块提供。

## Windows检出差异

本次下载的normalized_samples/AUTH-001/B.js使用CRLF，Git对象及元数据哈希按LF记录。已核对只存在53处换行转换，逐行代码一致，且文件与工作包2开始前相同；本部分不修改该文件。工作包1的字节哈希核验在此环境可能因此失败，不能解释为代码被篡改或漏洞误报。固定版本重建、检出换行规则或哈希口径由工作包1负责人确认，正式评测记录实际输入哈希。

## 给工作包3

读取rules和output_schema，把输入可控、路径可达、防护适用、身份权限和部署条件映射到三级推理框架。high、medium、low是证据等级，不是概率。静态存在候选与实测确认分别记录；一般风险、代码质量问题和目标漏洞分开。

位置采用片段ID与标准化局部行号，原始位置仍通过工作包1的line_maps追溯。多包缺失时标partial，共享片段按父样本与数据流归并。条件或代码证据的修订需要反馈样本、输入版本和实际位置，不直接改写模型原文。

## 给工作包4

接收完整Prompt、未经覆盖的模型输出、POC草案、依赖、参数、运行步骤及成功条件。本会话示例位于trial；正式评测表仍待填。试用POC均为需人工适配、未运行，Python语法检查不代替靶场验证。

按工作包1的固定源版本部署完整靶场，不将审计片段当独立页面。记录基址、PHP/数据库、浏览器、操作系统、登录与token、配置和专用测试对象；修改仅使用专用数据并提供恢复步骤。不要提交Cookie、实际口令和token。

验证每条候选的具体前置条件，保存原始脚本、适配差异、运行命令和响应或页面证据。优先核验SQL正常与布尔对照、XSS浏览器无害标记、命令额外回显和越权保护数据。负例也需要按目标路径复核，不能以脚本失败证明安全。

## 反馈字段

| 字段 | 内容 |
| --- | --- |
| sample_id / finding_id | 父样本与候选编号 |
| input_version / prompt_version | v2输入及v1、v2或final提示词 |
| condition_key | 角色、配置、对象和状态的稳定组合 |
| evidence_path | 原始输出、脚本、日志、响应或页面证据 |
| location_review | 定位正确、错误或无法判定及原因 |
| poc_result | 完成验证步骤、失败、无法运行、未运行或证据不足 |
| failure_kind | 脚本、环境、认证、上下文、观察或漏洞判断 |
| ground_truth | 有漏洞、无所关注漏洞或证据不足 |
| requested_change | 需要修订的规则、POC要求或补充上下文 |

工作包2收到反馈后更新迭代记录和评测表，按相同样本与条件复测。工作包1的问题只反馈给其负责人；本部分不自行重建或改写上游输入。串行协作、提交和推送按仓库README执行，由成员检查后操作。
